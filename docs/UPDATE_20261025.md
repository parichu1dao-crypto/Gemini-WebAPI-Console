# Cookie reliability update / Cookie 稳定性更新

## English

This update keeps Cookie HTTP generation as the default (`cookie_protocol: legacy`).
It does not silently switch to browser generation or a cheaper model.

- Reuse an authenticated session instead of reconnecting before every turn.
- Adopt a newly imported cookie jar before the next request under the account lock.
- Recover authentication before the second strict-Pro eligibility check.
- Distinguish empty output, upstream service messages, and pre-submission authentication failures.
- Return `503/not_submitted` for preflight authentication or Pro eligibility failures;
  consumers should not count these as failed generations or trigger model failover.
- Verify the supported Pro response model identifier. Missing/mismatched evidence is
  rejected, not retried. This is upstream metadata checking, not cryptographic proof.
- Share one deadline between the HTTP handler and generation, preserving submission state.
- Detect an unavailable enrolled browser without logging credentials.

An explicit experimental `process-session` protocol is included for compatibility
diagnostics. It needs an enrolled browser for validation; generation still uses HTTP.
It is not the default and is never selected automatically. Upstream compatibility
may change. Argon is usable only when exposed and permitted by the upstream account.

### Upgrade and use

1. Finish/drain active requests, back up private `data/`, and update the code.
2. Run `python -m pip install -r requirements.txt`.
3. Keep your existing private settings; do not overwrite them with the example.
4. Start `python app.py`; see [Quick start](QUICKSTART.md) for setup and API examples.
   Existing standalone deployments may run `python service.py` and `python console.py`.
5. For `UNAUTHENTICATED`, open the account's enrolled browser, verify its identity,
   and import the refreshed session using `python import_browser_session.py --help`.
   Ordinary Cookie generation does not require browser interaction, but automatic
   recovery needs that enrolled browser to be reachable. Membership alone does not
   make an expired cookie valid.
6. Confirm `/health`, then send one short request before resuming a large batch.
   A healthy port alone does not prove generation works. Do not blindly replay
   `submission_uncertain` requests.

On October 25 a private deployment passed a short Pro request through the formal
Cookie API. This does not certify all accounts, long-text reliability, or future
availability. Credentials, account names and generated private text are excluded.

## 中文

本次仍默认使用原 Cookie HTTP 协议（`cookie_protocol: legacy`），不会自动切换网页生成或降级模型。

- 复用有效登录会话，避免每次请求都重新建连；新导入 Cookie 在账号锁内于下次请求前加载。
- 第二次严格 Pro 检查遇到登录失效时先尝试恢复，而非直接误判资格。
- 区分空回复、上游服务提示、发送前鉴权失败；发送前鉴权/资格失败返回 `503/not_submitted`。
  调用方应将其视为未提交，不计作生成失败，也不要因此触发备用模型路由。
- 校验支持的 Pro 响应模型标识，缺失或不匹配即拒收，不盲目重发；这不是密码学证明。
- 统一接口与生成的超时预算，保留实际提交状态；浏览器恢复入口离线时给出安全诊断。

同时包含显式选择的实验性 `process-session` 协议，用于兼容性诊断：浏览器只用于校验，
正文仍走 HTTP。它不是默认项，不会自动启用。Argon 是否可用取决于上游动态列表与账号权限。

### 更新与使用

1. 等待在途任务结束或排空服务，备份私有 `data/` 后更新代码。
2. 执行 `python -m pip install -r requirements.txt`，保留已有私有配置，不要用示例覆盖。
3. 执行 `python app.py`；首次使用参阅[快速开始](QUICKSTART.md)。
   原独立部署也可分别执行 `python service.py`、`python console.py`。
4. 遇到 `UNAUTHENTICATED`，打开该账号绑定的浏览器，核对身份并重新导入 Cookie；
   导入参数见 `python import_browser_session.py --help`。普通 Cookie 生成不操作浏览器，
   但自动恢复需要绑定浏览器可连接；有会员不代表旧 Cookie 仍有效。
5. 检查健康接口后先发一次短请求，再恢复大批量任务；端口在线不等于正文可用。
   遇到 `submission_uncertain` 必须核对结果，不能盲目重发。
